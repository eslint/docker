# ESLint Docker Language Plugin

A Dockerfile language plugin for [ESLint](https://eslint.org), providing:

- an ESLint-style **parser** for Dockerfiles (wrapping
  [dockerfile-ast](https://www.npmjs.com/package/dockerfile-ast), the parser
  behind Docker's official language server) that produces an ESTree-style
  syntax tree,
- an ESLint **language** implementation so rules can traverse that tree,
- **rules** inspired by [hadolint](https://github.com/hadolint/hadolint)
  checks and the
  [Dockerfile best practices](https://docs.docker.com/build/building/best-practices/),
  and
- a **recommended configuration**.

## Installation

```bash
npm install --save-dev eslint @eslint/docker
```

Requires Node.js `^20.19.0 || ^22.13.0 || >=24`. Tested with ESLint v10.

## Usage

Add the plugin to your `eslint.config.js`:

```js
import { defineConfig } from "eslint/config";
import docker from "@eslint/docker";

export default defineConfig([
	{
		// use the recommended rules for Dockerfiles and Containerfiles
		files: [
			"**/Dockerfile",
			"**/Dockerfile.*",
			"**/*.dockerfile",
			"**/Containerfile",
		],
		plugins: { docker },
		extends: ["docker/recommended"],
	},
]);
```

Or configure it manually:

```js
import { defineConfig } from "eslint/config";
import docker from "@eslint/docker";

export default defineConfig([
	{
		files: ["**/Dockerfile"],
		plugins: { docker },
		language: "docker/dockerfile",
	},
]);
```

## Configuration comments

ESLint configuration comments work inside Dockerfiles. Note that Dockerfile
comments must start at the beginning of a line (a trailing `#` is part of
the instruction's arguments), so use `eslint-disable-next-line` rather than
`eslint-disable-line`:

```dockerfile
# eslint-disable-next-line docker/no-maintainer
MAINTAINER jane@example.com

# eslint-disable docker/require-image-tag
FROM node
# eslint-enable docker/require-image-tag

# eslint docker/no-sudo: "warn"
```

## Syntax tree

The tree format is documented in [docs/syntax-tree.md](docs/syntax-tree.md).
Nodes carry `start`/`end` character offsets instead of `range`/`loc`
properties; use `sourceCode.getRange(node)` and `sourceCode.getLoc(node)`.

The parser is also exported directly:

```js
import { parseDocker } from "@eslint/docker";

const { ast, comments } = parseDocker("FROM node:20-alpine\n");
```

Parsing never fails: the underlying parser is error-tolerant, so malformed
input still produces a tree.

## Development

```bash
npm install
npm test          # unit + integration tests (Vitest)
npm run lint      # ESLint on the plugin's own sources
npm run fmt       # Prettier
npm run build     # compile TypeScript to dist/
```

Pre-commit hooks (via [yorkie](https://www.npmjs.com/package/yorkie) and
lint-staged) run Prettier and ESLint on staged files. Releases are managed
with [release-please](https://github.com/googleapis/release-please) through
GitHub Actions.
